# Registro LBDP

## LBDP-01 — Esqueleto público

- Alcance: [aceptación](iterations.md#lbdp-01--esqueleto-público). App independiente `@damaca/lbdp`, portada, dos categorías, siete fichas, clases, bonos, celebraciones, servicios y contacto: 18 páginas. Next.js del catálogo, componentes de servidor y una cabecera cliente para el menú. Sin conexión a otras apps, API, base de datos, auth, carrito o pagos.
- Identidad: oliva/crema, serif editorial, logo y trece imágenes locales WebP del negocio (menos de 1 MB en conjunto), con fuentes documentadas; las imágenes de talleres se recortan para retirar el pie de cartel. Sin fuentes ni fotos remotas en runtime. Noindex/robots de preparación; condiciones, fechas/precios y compras enlazan explícitamente a la web actual. Contacto usa correo/teléfono/WhatsApp reales, sin formulario simulado ni dirección pendiente de confirmar.
- Integración de workspace: solo entradas de lbdp en `bun.lock`, referencia de producto en el plan raíz y una entrada nueva en la matriz CI de tipos filtrados. Ningún archivo de otra webapp modificado; sin cambios en versiones o tareas compartidas.
- Validación: `bun install --offline` pasa tras habilitar escritura en la caché Bun (primer intento restringido dio EPERM); `bun run type-check --filter=@damaca/lbdp` y `bun run build --filter=@damaca/lbdp` pasan. Biome explícito de lbdp sin errores, avisos ni infos; lint incremental previo al staging comprueba cero archivos nuevos, por lo que no se usa como única evidencia. `bun run lint --staged` comprueba 21 archivos sin hallazgos; diff check pasa al cierre.
- HTTP sobre el build de producción: las 18 páginas enlazadas devuelven 200, cada una con un H1 y noindex; 13 URLs de imagen funcionan; rutas desconocidas editorial/producto devuelven 404; robots desautoriza indexación. Revisión de React: componentes compartidos, solo estado de menú, IDs accesibles y excepciones Biome justificadas para exports requeridos por Next y landmark único de salto.
- Navegador: las 18 páginas a 390 y 1440 px (36 comprobaciones) sin overflow horizontal, H1 ausente/duplicado ni imágenes rotas detectadas; consola sin errores. Capturas de portada escritorio/móvil y ficha móvil. Menú abre/cierra y se cierra al navegar; recorrido listado→ficha y enlace a la ficha vigente confirmado. No se ejecutan compras o envíos. Se restaura viewport y se detiene la previsualización propia al finalizar.
- Documentación: enlaces locales revisados; tres documentos de planificación y AGENTS propios, README con comandos de ejecución e integración futura. No se añaden tests unitarios que dupliquen contenido estático; la evidencia funcional procede de HTTP y navegador. No se certifican accesibilidad completa, pagos, backend o despliegue remoto.
- Publicación: commit y coincidencia del SHA de `origin/int` se comprueban en Git durante el cierre. Sin cambios de `main`, proyectos Vercel o dominio. La integración Git existente puede reaccionar al push; no se realiza despliegue manual.
- Capacidad inicial: 41% de 5h y 45% de 7d; antes de validar el build final, 34%/44%. Trabajo secuencial, dentro de reservas de 7%/2%; lectura final comunicada después de verificar publicación.
