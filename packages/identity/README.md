# Shared identity package

`@damaca/identity` contains the Damaca Hub OIDC provider, reusable consumer integration, UserInfo contract, and stable Vercel origin resolution for future consumers. Google credentials remain in Damaca Hub. Pocha Score and Card Wars are public static PWAs and do not consume social login.

## Hub clients

Google authentication remains centralized in Hub. Administrators manage one OIDC client for each existing private application and environment from the Hub administration screen. Dynamic client registration stays disabled. Client IDs are generated by the server; client secrets use 256 bits of random data, are stored only as SHA-256 hashes, and are shown once at creation or rotation.

Register the exact callback URL ending in `/api/auth/callback/damaca-hub`. Production and `int` use separate clients. A stable Vercel branch alias can serve as the `int` base URL; per-commit deployment URLs need explicit registration. Changing a catalog link only changes the suggested callback and never changes an existing client automatically. Editing a callback applies to subsequent protocol requests without restarting Hub. Disabling a client blocks new authorization and token exchanges and revokes its access and refresh tokens. Rotating its secret invalidates the prior secret and delegated tokens.

The one-time `db:migrate-public-games` task removes game grants and old game client/token records and imports non-game clients from the legacy `HUB_OIDC_CLIENTS` value. It matches callback origins to the production and preproduction links already stored in the catalog. The legacy variable is migration input only; normal Hub runtime does not read it. Run this task only after confirming the target database and catalog links.

## Consumer origins

`resolveConsumerOrigin` accepts an explicit environment URL when configured. Otherwise it uses `VERCEL_BRANCH_URL` for `int` and `VERCEL_PROJECT_PRODUCTION_URL` for production. Both system values omit the scheme, which the helper supplies as HTTPS. It deliberately does not use `VERCEL_URL` or request headers, because those can refer to per-commit deployments or untrusted hosts.

Consumers still require their own Hub client ID, client secret, and independent session secret. Their sessions and cookies remain isolated from Hub. The shared factory validates Hub discovery, S256 PKCE, state, nonce, issuer, audience and signed ID tokens. It accepts an optional Better Auth database adapter and model-name mapping so existing consumers can retain their local user IDs and storage. UserInfo derives the app from the validated token's registered client and checks current catalog/grant state. Mongo or Hub failures deny access.

## Storage and validation

Pocha Score and Card Wars are static PWAs. Their IndexedDB data, offline shell and JSON import/export do not require authentication. Dalis Tasks & Events uses the shared consumer factory with its existing Mongo models so Hub identity links to existing local user records; Hub access is checked for protected server work while its prepared local shell remains usable offline.

Run focused checks from the monorepo root:

```bash
bun run type-check --filter=@damaca/identity --filter=@damaca/damaca-hub
bun run test --filter=@damaca/identity --filter=@damaca/damaca-hub
bun run build --filter=@damaca/damaca-hub
```

The package integration tests run the Hub and consumer protocol handlers over isolated HTTP servers with a seeded identity and in-memory auth adapter. They do not contact Google or prove MongoDB persistence across restarts. Live Google, MongoDB, Vercel callback routing and native installation must be recorded separately.
